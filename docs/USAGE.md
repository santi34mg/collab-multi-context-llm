# Usage guide

Run these commands from the repository root with a Rust toolchain supporting edition 2024. The built-in student, demo, and ordinary tests do not require model weights, a GPU, or API keys. For pretrained GGUF inference and teacher collection, see [Inference and distillation](INFERENCE.md).

## Collaboration and persistence demo

```text
cargo run --release -- demo memory.json trace.json
```

Two scripted streams publish private arithmetic clues. One proposes an edit to the other's working entry; the owner accepts it. A selected result is staged for memory, both streams finish, and the engine commits and saves the memory. The demo then reopens the file into a fresh session and retrieves the result.

Operations travel through the same one-byte-per-stream-per-round interface used by the model. The policy and arithmetic in this demo are scripted, not learned. Repeated runs append memory entries without deduplication.

The optional `trace.json` records generated bytes, operation results, and memory commits. Traces are private host diagnostics: they may contain sensitive content and are not automatically shared with streams. Without arguments, `demo` uses `memory.json` and does not write a trace file.

## Train the peer-information smoke test

```text
cargo run --release -- train 12000 checkpoint.json
```

Each stream receives a private `A`/`B` bit. After scripted publication, the model predicts the other stream's bit for both streams in one forward pass. Training and evaluation use all four input combinations. The command reports loss, accuracy out of eight stream predictions, and a publication-disabled ablation.

This tests learned use of peer information, not learned publishing, generalization, or autonomous collaboration. Short runs can learn the output alphabet while remaining at chance on the actual task. This checkpoint is not trained to generate JSON operations.

The extended regression test holds private input fixed while changing peer-publication content, and separately masks peer-publication attention:

```text
cargo test --release --test learning -- --ignored
```

## Train operation generation from demonstrations

```text
cargo run --release -- train-trace examples/collaboration-dataset.json 10 checkpoint.json
```

The dataset is a JSON array of episodes. Each episode contains:

- `scope`: the fixed application memory namespace;
- `working`: one list of initial working entries per stream;
- `memory`: optional seed memory drafts;
- `rounds`: groups of stream operations whose frames begin together.

The [example dataset](../examples/collaboration-dataset.json) covers publishing, proposing and accepting an edit, selecting memory, and finishing.

The trainer serializes each operation as a JSON line and teacher-forces the next byte for every participating stream. Shorter frames wait while peers complete theirs. Every demonstration is replayed and context-checked before training; invalid actions are rejected rather than used as successful targets. Loss is averaged per supervised byte, not per action.

To reuse a distilled student, supply its checkpoint as the fourth argument:

```text
cargo run --release -- train-trace examples/collaboration-dataset.json 10 checkpoint.json target/student.json
```

Without an initial checkpoint, this command initializes a new student. See the [distillation workflow](INFERENCE.md#train-and-reuse-the-student) to create one from teacher answers.

The example is one small demonstration, not a training corpus. Low teacher-forced loss does not establish that free-running generation will produce valid operations or solve a task. Numerical failure can occur after earlier successful updates: an entire training episode is not an optimizer transaction.

## Run a checkpoint without teacher forcing

```text
cargo run --release -- run checkpoint.json examples/finish-episode.json 256 memory.json
```

Unlike `train-trace`, `run` takes one episode object, not an array. It uses only the episode's initial state and ignores demonstration `rounds`. The [finish example](../examples/finish-episode.json) illustrates the input schema, not a guarantee that a checkpoint will solve it.

Each decoding round computes all active distributions from the same snapshot, greedily selects one byte per stream, and applies completed operations at the boundary. Malformed operations are rejected and fed back to their originating stream. Generation stops when all streams finish or the round limit is reached.

The optional memory file is loaded before the task and saved after a successful task-boundary commit. Without it, committed memory stays in RAM. An unfinished task never saves staged memory. Episode seed memories are appended even when loading a file; omit them when they should not be reinserted.

JSON diagnostic events go to standard output; status goes to standard error.
